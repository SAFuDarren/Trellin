# macOS 版 Trellin

Trellin 在 macOS 原生窗口中打开 Research Multiplier 工作台。本地构建面向使用 Apple Silicon 的 macOS 15 及以上设备。应用自带 Python 和工作台。初次使用前，按[课题设置指南](research-foundation.md)准备本机 PostgreSQL、pgvector 和 Lean。课题目录由你选，放在软件目录外。

## 使用 Trellin

1. 把 `Trellin.app` 放进系统或个人的「应用程序」目录，然后从 Launchpad 打开。没有上次打开的课题时，Trellin 会在 `~/Library/Application Support/Trellin/Library` 的库中新建并打开名为「我的研究」的项目。
2. 用「文件 → 新建课题…」在库里建独立课题，用「文件 → 打开课题…」切换已登记课题。每个课题有各自的 ID、文件和 PostgreSQL 绑定。
3. 用「文件 → 打开文件夹…」或 **⌘O** 打开指定位置的课题。选择普通研究文件夹时，Trellin 把工作区建在应用库中，并在库里关联所选目录。再次选择同一文件夹会打开同一项目。可以直接选择已初始化的工作区，也可以重新打开已有 `Trellin` 子目录中的项目。原始研究文件保留在原位置。此前只用环境变量配置的课题，请先用已有设置流程保存数据库登录信息。
4. 选择图谱节点，再按 **⌘Q**。下次会恢复上次成功打开的课题，原节点仍存在时也会恢复。已有课题从登记位置打开。库由 Trellin 自己维护：上次的课题无法重新打开时（例如它属于另一个 Trellin 安装，或文件夹已被删除），Trellin 改为打开你的库，并用一条带「打开课题…」的简短提示说明。
5. 数据库暂时离线时，服务恢复后点「重试」。应用使用装有 pgvector 的本机 PostgreSQL 18，默认是 `/tmp` 下的 Unix 套接字和 `5432` 端口。其他本机安装可通过 `RM_DESKTOP_PG_SOCKET` 和 `RM_DESKTOP_PG_PORT` 指定。数据库升级按[工作台设置说明](proof-workbench.md)操作。

左侧导轨分为五个空间：「主页」「工作」「对话」「团队」和「自动化」。「主页」直接打开导轨旁的「项目图谱」，底部的缩放控件旁会显示连接状态。「工作」直接打开课题看板。侧栏最上面是「等你判断」：待批准的结果、待回答的问题、检查失败和 Agent 交付，按时间从新到旧排列，每项一行，指向某一行时才出现「处理」和「打开页面」。「等你判断」是待办的唯一计数：导轨角标数的是同一批项，标题下的小标签可以只看一类，比如待批准的结果或待确认的起始范围。「视图」统计全部课题、运行中的工作、有卡点的课题和「现在可推进」的课题（所依赖的课题都已证明的进行中课题）；「置顶」放你置顶的课题；「记录」打开「判断记录」「Agent 任务」和「定理库」。每一节都可以点标题折叠，记录页面自己的分组（比如定理库的类型和来源）挂在它的入口下面，可以一起折叠。点「处理」「逐项处理」或看板上的课题卡片，会在页面标题下方打开一个浮在看板上的窗口；看板保持原样，条目所属的课题会被标出，看板本身不会移动；卡片被窗口挡住时，可以手动滚动看板把它露出来。拖动窗口左边缘，或选中左边缘后按方向键，可以在 420 到 900 像素之间调整宽度，双击恢复默认，宽度会被记住：在面板里记录决定后，下一项会接着显示；按 J、K 在列表中移动，按 Esc 关闭。待确认的起始范围会列出起始陈述和每个待决定的条目：逐项选择「确认」或「略去」，没有 Lean 命题的条目补上命题，再写一个理由即可。在「判断记录」页点「处理」，条目会在页面里打开，而不是在旁边再开一份。暂时还不能在工作台记录的审阅条目会直接说明这一点，不会让你去用命令行。卡片标出课题是怎样确立的：「Lean 核验」「证书核验」或「审计证明」，审阅中批准了这份证据时会带一个勾；进行中的课题若只有数值检查支持、尚未证明，标为「数值支持」。卡片还列出它依赖的课题，以及有多少课题引用它；指向或选中卡片，会突出这两边并淡化其他卡片，侧边面板在「依赖」和「被引用」下列出它们，点一下就在面板里打开。在导轨顶部的课题方块切换或新建课题。指向某个项目并点「⋯」，可以重命名，或将它从列表中移除。移除不会删除项目：文件夹和数据库仍保留在这台 Mac 上，用「打开文件夹…」即可重新添加。当前打开的项目和「我的研究」不能移除。有了自己的项目后，空的「我的研究」不再出现在列表中；其他项目都无法打开时，Trellin 仍会打开它。打开课题文件夹、更改库位置在「设置 → 高级」。「自动化」页从「新建自动化」和两个模板开始：「复用与归约 Lean 证明」不调用模型，尝试现成的 Lean 归约和可复用的证明；「跟踪已验证的证据」只记录已有证据带来的进展。选好模板和课题后会显示完整规则供你检查，点「批准并运行」之前什么都不会运行。「停止」需要填写理由，已有结果和运行记录都会保留。[自动化](research-progress.md)

在工作台任一页面按 **⌘K**（其他平台用 **Ctrl+K**），或点击左侧搜索按钮，打开「命令面板」。可以搜索当前项目的课题或证明节点标题、`FLOW-09` 这样的完整引用编号，以及文库条目、对话和 Agent。当前课题的证明节点优先显示，随后是全局图中最近 40 个课题的匹配节点。输入完整的已保存引用编号可直接打开更早的节点。命令面板也能打开「新定理…」「论文、笔记或代码…」「研究引用」、当前选中课题的「证明任务」，或发起新对话。需要提交的操作在对应面板里确认。

项目图、命题看板和详情栏显示已记录的证明义务和验证数量。尚无记录时，可查看进度标签中的说明。在命题看板或详情栏点「待审核结果」，可打开该命题对应的审核记录。

项目图谱标题栏的 **+** 按钮（「添加到项目」）用来带入材料：「论文、笔记或代码…」打开导入，「新定理…」录入一条定理。把文本、Markdown、TeX 或 Lean 文件拖到图谱任意位置即可导入；还没有课题的项目会在图谱中间显示拖入区。图谱上的工具都是图标，悬停或聚焦时显示名称。针对单个课题的操作，如「本地引理」「前提」「研究引用」，在课题的右键菜单里。

在项目图谱点「查找课题」搜索并选中卡片。在「Agent 对话」的选择器里搜索接收方或对话。在这些搜索框和命令面板中，用方向键移动，按 **Enter** 确认选择，按 **Esc** 返回原控件。

在命令面板输入 `#` 可缩小到课题、证明节点和已保存引用，输入 `@` 可缩小到 Agent。底部显示这些前缀和导航按键。菜单或面板打开时，可以按结果旁显示的快捷键，例如 Mac 的 **⌥P** 或其他平台的 **Alt+P**。

在活动抽屉中点「打开完整活动」，可在整页查看同一份活动列表。「团队 → 任务队列」另列每个证明与模型任务的模型、服务商和运行时长。导轨上的「工作」图标显示等你处理的数量。

在导轨底部的「帮助」中查看项目图谱、Agent 任务和证明验收的简明指南。每份指南都可以打开对应的工作台页面。按 **?**，或在「帮助」中打开「键盘快捷键」，即可查看当前平台的快捷键。「详情」和「全局图」图标会显示各自面板的开启状态。焦点位于项目图谱或其工具栏时，按 **I** 切换详情栏，按 **M** 切换全局图。将指针悬停在图标上，或用键盘聚焦图标，即可查看对应快捷键。

证明页标题栏显示从项目图谱到课题和当前节点的路径。点击课题名称回到目标节点，点击图谱入口返回画布。在「Agent 任务」中，交接任务的路径可以打开交接来源。

当前课题和节点会写进地址，格式为 `#workbench/claim/<课题 ID>/node/<节点 ID>`。用浏览器的后退和前进可以在图谱、课题和之前打开的课题之间切换；复制地址即可回到同一份证明。在同一份证明中改选节点只更新地址，不会多出一步后退。如果课题或节点已不存在，会打开图谱或课题目标，并给出提示。

焦点位于画布时，方向键用来平移。要移动已聚焦的卡片，按 **⇧F10**（其他平台用 **Shift+F10**）打开卡片菜单，选择「移动卡片」。用方向键预览位置，按住 **Shift** 可加大步长。按 **Enter** 保存，或按 **Esc** 取消。

打开证明后，画布会以便于阅读的缩放比例显示节点。点「适合窗口」查看全图。选中节点可在右侧详情中阅读完整公式和 Lean 陈述。将指针悬停在活动计数上，或打开详情，可查看记录里的 Agent 和模型。底栏显示带标签的证明状态计数。窗口太窄、标签放不下时，点「状态」查看完整计数。点「连线样式」查看当前视图的图例。切换到「引用关系」后，可以根据线型区分已使用的引用、允许使用的前提和计划中的步骤。

切换界面语言后，证明节点的排列顺序、引用编号和已保存的卡片尺寸保持一致。

在「撤回影响」中，图例和详情栏显示相同的受影响记录总数，涵盖其他课题的记录，并单独标出正在预览的前提。切换回「证明进展」即可使用证明任务等操作。

详情栏较窄时，受影响记录的名称占一整行，状态另起一行。影响统计显示在列表标题下方。

选中的项目图卡片、证明节点和待审核条目带有海军蓝边线和浅底色。指针悬停时显示中性色高亮，键盘聚焦时显示独立的外侧描边。证明节点内的转圈图标和数字显示正在运行的任务。

从卡片底部的连接点拖向另一项课题即可建立关联。移到可连接的卡片上时，预览会显示保存后的走线，并标出两端在卡片上的接点。选中连线可查看两端的课题名并移除关联，移除后可以撤销。

单击项目图谱的卡片可查看详情。双击卡片或聚焦后按 **Enter** 打开证明，点「项目图谱」或按 **Esc** 返回。窗口较窄时，第一次按 **Esc** 会收起详情抽屉，并保留当前选中的节点。缩放按钮位于画布下方。右键点击卡片或证明节点，或聚焦后按 **Shift+F10**，可打开操作菜单。「写证明意见」会打开该节点的编辑框，「在文库中查看」会显示该课题已记录使用的来源。

打开 **Agent 对话** 即可开始输入。在草稿开头按 **@** 可以选择收件人。新对话会选中你最近交谈的 Agent；还没有对话时选中第一个已保存的 Agent，并显示它的名字。从选择器换成其他收件人后，草稿会记住这个选择。如果项目没有 Agent，可以点击 **添加 Agent**。建议只会填入草稿。选择 **请求详情** 会在本机打开对话，并显示即将发出的内容。按 **Enter** 或点击 **发送** 即可发送。在命题或证明节点上选择 **询问 Agent** 可以附加对应的上下文。点击 **打开完整对话** 后，同一对话及草稿会进入 Chats，底部面板会收起。

Agent 对话悬浮在内容区右下，避开详情栏和图谱控件。拖动上边、左边或左上角可以调整大小。用键盘聚焦边缘后，可用方向键调整。点「最大化 Agent 对话」展开到可用范围，再点「恢复对话大小」回到之前的尺寸。收起面板、切换页面或重开应用后，仍会记住尺寸。草稿建议会随选中的命题或证明节点变化。在已有对话中勾选「发送时省略此前消息」，发送时就不会附上之前的消息。对话记录仍保留。

从底栏打开「Agent 活动」，可以查看已记录的证明与模型任务、Agent 任务、对话和待审结果。按状态筛选，点开条目即可回到任务、证明、对话或审阅。团队徽标显示项目的运行总数，课题和对话按各自显示的课题或证明节点计数。暂无活动时可以直接打开 Agent 任务。没有消息的对话会按输入区和建议的高度展开。

「工作 → 判断记录」按时间从新到旧列出你和其他人记录过的判断：批准或退回的结果、确认的起始范围，以及冻结、撤回或恢复的课题，每条都写明谁做的决定、理由和时间。可以只看结果、课题或起始范围，也可以从某条记录直接打开它的课题。还在等你的事项在「等你判断」里，「工作」徽标数的是同一批事项。

结果待审阅时，可从「等你判断」打开，也可从检查器的「审阅」或上方队列打开。写下理由（也可以点建议的理由），然后点「批准并下一项」（按 **⌘↵**，其他平台按 **Ctrl+Enter**）或「退回」，下一项会接着打开。批准会记录对证据的接受，决定同时记录审阅人。

详情栏较窄时，点「更多课题操作」即可使用主操作旁放不下的选项。

在文库中，将指针移到条目上或用键盘聚焦条目，即可看到「编辑陈述」图标。聚焦后按 **Tab** 再按 **Enter**，即可打开修订表单。也可以从条目详情打开表单。

项目图谱、课题详情和「课题」看板会显示已记录的审核、待决定和验证状态。选择课题可以读取当前证明任务。进度统计当前 Lean 陈述的各条归约路线中已记录的证明义务。义务的已核验证明仍然有效时，计入已验证数。同一命题出现在两条路线中时，各计一次。

在「工作 → 课题」中，用「显示」选择排列：「按领域分行」每个领域一行、每种状态一列，「状态看板」只按状态分列，「列表」逐条排列，「表格」对齐各项属性。课题默认按领域分行。各列按窗口宽度平分，单列有宽度上限；除「进行中」和「已证明」外，没有课题的状态不占位置，所以只有窗口很窄时才需要横向滑动，滑动时领域名留在左侧。领域行可以折叠成一行计数。每张卡片显示编号、标题，以及每条证明义务一格：已核验、运行中、未开始或失败。「显示」还可以设置密度、已证明的课题显示为卡片还是一行，以及每格最多显示几张，其余收进「再显示 N 项」。「筛选」按领域和状态缩小范围，每个生效的条件显示为顶栏下的标签，点 × 去掉。「搜索」匹配编号、标题或领域，「新建课题」打开「新定理」。在「工作 → Agent 任务」中，从「显示方式」选择「看板」「列表」或「表格」，默认使用列表。本机分别记住两个页面的布局。各种布局下均可打开课题预览或任务详情。

在列表或表格中，用复选框选择条目。按住 **Shift** 点击另一个复选框，可以选中两者之间的条目。焦点在列表或表格内时，按 **⌘A**（Windows 上用 **Ctrl+A**）选择所有可见条目，按 **Esc** 清除选择。「复制记录编号」按当前显示顺序复制选中的课题或 Agent 任务编号。

打开「团队」时默认进入「执行者」。在[「团队 → 运行环境」](project-intake.zh-CN.md#连接模型)选择已安装的模型，「环境检查」在该页面有独立区块。集中部署如需使用非标准目录下的命令，可在 Trellin 的启动环境中用 `RM_DESKTOP_TOOL_PATH` 指定工具目录。目录必须是绝对路径，以冒号分隔。

「证明活动」提示课题库版本较旧时，点「备份并升级」，核对 Mac 对话框中的课题路径。Trellin 先验证包含课题文件和 PostgreSQL 快照的本地备份，再升级此课题的数据库并重新打开课题。请保留备份供恢复使用。升级需要此课题已保存的数据库所有者登录信息。备份使用不低于服务器主版本的 PostgreSQL 客户端工具（`pg_dump`、`pg_restore`）。Trellin 优先选与服务器主版本相同的客户端，其次是最接近的更新版本；除了 `PATH`，还会查找 Homebrew 的 `postgresql@N`、Postgres.app 等常见安装位置，所以 `PATH` 上较旧的客户端不会再导致备份失败。找不到合适的客户端时，提示会写明需要安装的版本。命令行备份可以用 `--pg-bin` 指定目录，`research-multiplier doctor` 会显示将使用的客户端。

## 存储管理

默认位置无需任何操作。迁移库是高级功能，例如要把库放到另一块磁盘时使用。从 macOS 菜单点「Trellin → 设置… → 存储」，或按 **⌘,**，查看当前库的位置并在 Finder 中打开。点「迁移数据…」选择新位置的上级文件夹。Trellin 会在预览显示当前路径和新建的 **Trellin Library** 目录。确认后先复制并核对文件、课题 ID 和数据库绑定，再切换登记位置。旧库保留为恢复副本，迁移中断或校验失败时原库继续可用。已管理课题的新路径可从「打开课题…」进入。

迁移覆盖库、库自身设置和其中集中管理的课题文件。外置课题和显式导出的文件保留在原位置。PostgreSQL 继续使用原有数据位置和绑定。应用支持目录保存精简的位置记录和应用设置。上次打开的课题和选中的节点按课题 ID 保存在库自身的设置文件中，随库一并迁移；旧版的 macOS 偏好（`lastWorkspaceV1`）只迁移一次，之后不再读取。若库的注册表或锁文件缺失，Trellin 会在打开前根据已管理工作区的 `.trellin-managed.json` 标记自动重建（迁移数据后同样生效）。数据库登录保留在受保护的配置中。

已有的[课题备份](research-foundation.md#recover-and-monitor)可同时保全课题文件和 PostgreSQL 快照。备份应用设置时，另外保存应用偏好及已登记的库位置。课题归档也可以恢复为独立课题。

点导轨底部的齿轮打开「设置」。设置只在原地修改：语言、布局、键盘快捷键、更新，以及 Mac 版的「高级」。设置不链接到其他页面：模型连接和运行环境在「团队」，自动化规则在「自动化」。可以搜索设置中的控件，例如「键盘快捷键」。在 Mac 版中语言和布局偏好保存在这台 Mac 上，在浏览器中则保存在当前浏览器。要找其他内容，请用命令面板（**⌘K**）。

在「设置 → 更新」可以查看已安装版本，也可以手动检查是否有新的稳定版。自动检查默认关闭。开启后，工作台运行期间每 24 小时最多检查一次。检查只向 GitHub 请求公开的版本信息，不发送课题数据或凭据。你可以在浏览器中打开更新说明，自行决定何时安装更新。

## 构建本地审阅版

使用装有 Xcode 命令行工具和 Git 的 Apple Silicon Mac。从包含已构建工作台的 Git 工作树运行，需要通过 HTTPS 下载运行环境和软件包。构建会核对运行环境和软件包的哈希。请预先建立软件目录之外的输出目录。

工作台打开前的各个画面（正在打开、选择文件夹，以及数据库不可用等问题）共用一个原生组件，使用与工作台相同的配色、字号和按钮样式。每个问题只给一个能解决它的主操作。课题出问题时引导回「打开库」，只有在选择文件夹的流程中才提供「打开文件夹…」。路径和错误代码收在「显示详情」里。要检查所有画面的浅色和深色效果，把它们渲染到源码目录外一个已存在的文件夹：

## 创建项目前预览选定资料

原生启动器提供私有的一次性命令，供后续项目导入界面使用。表中注明需要输入的命令从标准输入接收一个 UTF-8 JSON 对象，上限为 64 KiB。标准输出使用版本 1 的 JSON 响应。只有原生调用方接收本机路径、目录身份和原文出处。

| 启动器参数 | JSON 输入 | 成功响应 |
| --- | --- | --- |
| `--intake-inspect` | `{"root":"<原生选择器选中的绝对目录>"}` | `selection` 包含规范化后的 `root`、本机目录 `identity` 和 `workspace` |
| `--intake-preview` | 上一步返回的 `root` 和 `identity`，以及按选择顺序排列的 `references`，每项含 `path` 和可选的预期 `sha256` | `files` 按顺序返回各相对路径的结果 |
| `--intake-models` | 无 | `models` 列出可在本机运行的 Ollama 模型名称 |
| `--intake-draft` | 检查所得的 `root` 和 `identity`、明确选择的 `model`，以及每项均含 `path` 和预览所得 `sha256` 的 `references` | `draft` 返回带原文证据的可编辑草稿 |

若 `workspace` 非空，所选目录本身或其旧版 `Trellin` 子目录含有工作区标记，调用方应走正常的重新打开流程核验工作区。空值表示可预览文本。预览返回前会再次核对目录身份和工作区标记。目录校验失败或请求格式有误时，只返回固定错误代码，省略文件列表。

一次最多选择 16 个不同的相对路径。支持 UTF-8 的普通 TXT、Markdown（`.md`、`.markdown`）、TeX 和 Lean 文件。`available` 的文本结果包含相对路径、原始文本（包括原有换行符）和原始字节的 SHA-256。超过剩余文本限额的文件整份跳过。文本文件解码或摘要校验失败时，已读取的字节仍计入限额。

macOS 应用使用包内的 PDFKit 辅助程序预览有文本层的 PDF。成功结果包含 `path`、原始 PDF 字节的 `sha256`、`page_count`、`pages_included_through` 和 `pages`。`pages` 的每项包含从 1 开始的物理页码 `page` 和提取的 `text`。无法提取文本的页面不出现在数组中。`pages_included_through` 小于 `page_count` 时，预览只覆盖此前的页面。每页文本整页纳入或省略。

每次请求最多读取 16 MiB 的 PDF 原始字节，提取总时限为十秒。超过 128 页的 PDF 会单独提示。PDF 提取的文本与文本文件共享 18,000 字节限额。PDF 失败结果仅含 `path` 和固定 `status`，如扫描件的 `pdf_no_text`、`pdf_locked`、`pdf_invalid`、`pdf_page_limit`、`pdf_text_limit`、`pdf_timeout`，以及辅助程序无法使用时的 `pdf_unavailable`。材料无法读取时，可在现有导入流程粘贴选定文本或手动继续。

文件系统和文本失败沿用 `unsupported`、`missing`、`inaccessible`、`too_large`、`invalid_utf8`、`binary`、`empty`、`changed` 或 `unstable` 状态。资料检查和预览仅读取明确选择的资料，不调用模型。

### 在本机生成草稿

按用户确认的文件选择提交各份预览摘要。所选文件发生改动、读取不稳定、不可用或无法读取时，会在请求推理前停止。本机模型仅接收选中的段落文本和不透明标识符。路径、原始文件摘要和 PDF 物理页码留在私有启动器。模型发现和推理复用现有的本机 Ollama 选择流程。

临时 `draft` 返回建议的 `title`、`question`、`sources`、`items` 和 `links`。每项的可编辑标题 `label` 与逐字出处 `source.quote` 分开，出处还记录文件相对路径、原始摘要和适用时的物理 `page`。来源保留 PDF 的部分预览范围。`suggested_dependency` 从图项指向建议的前置图项。草稿条目及关系供研究者审核。生成过程不创建或更新项目、不保存模型对话，也不占用已打开项目的预算。

模型选择、推理或回复校验失败时，可返回 `intake-model-unavailable`、`intake-model-failed` 或 `intake-model-output`。可以检查输入或选择另一个本机模型。失败回复省略原文和模型服务诊断。

## 通过启动器核对已绑定的原目录

桌面启动器的私有存储命令按项目 UUID 查看、重新绑定和核对原目录，沿用版本 1 的返回格式。文件引用由该 UUID 和相对于原目录的路径组成。绝对路径只用于本机应用数据和私有存储交换。

| 启动器参数 | 标准输入的 UTF-8 JSON | `source` 中返回的字段 |
| --- | --- | --- |
| `--storage-source PROJECT_UUID` | 无 | `source_id`、`root`、`revision`、`status` |
| `--storage-rebind-source PROJECT_UUID` | 含 `expected_root`、`expected_revision` 和 `root` 的对象 | `source_id`、`root`、`revision`、`status` |
| `--storage-check-source PROJECT_UUID` | 含 `references` 的对象，数组元素包含 `path` 和可选的上次 `sha256` | `source_id`、`status`、`files` |

用户选定替换目录后，提交来源返回中的已保存路径和版本，原目录离线时也可操作。请求引用的旧绑定已变化时，返回 `storage-stale`，应重新读取绑定再重试。重复确认当前目录时保留绑定版本。同一路径被另一个目录占用时，需要重新显式确认。

核对在读取文件前，先比对打开的目录与保存的本机文件系统身份。身份不符时返回 `identity_changed`，目录打不开时返回 `unavailable`，能打开但缺少身份的旧绑定返回 `needs_confirmation`。课题在这些状态下仍可重开。身份只适用于本机文件系统，重新挂载或跨卷移动可能需要显式确认。

确认来源会更新应用管理区中的绑定标记。Trellin 1.0.151 无法打开更新后的标记。如需回到该版本，恢复升级前配套的应用数据和课题备份。

一次核对最多读取 16 个明确指定的普通文件，每个文件最多 4 MiB，返回路径、状态和已取得的 SHA-256。原目录不可用、尚未确认、身份不符或核对期间不稳定时，文件列表为空。可访问的原目录中缺失单个文件时，会单独报告。核对发现文件正在变化时返回 `unstable`，供调用方重试。核对过程拒绝符号链接，保留原文件内容和目录结构。这些命令供后续桌面界面对接。

### 核对和修复已登记的文件引用

登记文件时保存一条本机引用，包含稳定的 `id`、`revision`、相对 `path` 和记录的 `sha256`。一个托管工作区通过一份应用数据记录最多 128 条引用。引用随应用库迁移，属于本机定位状态，不进入可移植的科研归档。

| 启动器参数 | 标准输入的 UTF-8 JSON | `source` 中返回的字段 |
| --- | --- | --- |
| `--storage-list-source-references PROJECT_UUID` | 无 | `source_id`、`revision`、`references` |
| `--storage-track-source-reference PROJECT_UUID` | 含 `path` 和 `expected_revision` 的对象 | `source_id`、`revision`、`reference` |
| `--storage-check-source-references PROJECT_UUID` | 含 `reference_ids` 的对象，数组最多 16 个不重复的 UUID | `source_id`、`revision`、`status`、`files` |
| `--storage-repair-source-reference PROJECT_UUID` | 含 `reference_id`、`expected_revision`、`expected_reference_revision` 和选定 `path` 的对象 | `source_id`、`revision`、`reference` |

外层 `revision` 标识来源绑定版本，引用里的 `revision` 标识保存的文件位置版本。重复登记同一路径时沿用原摘要。成功的核对结果同时给出当前观察、`reference_id` 和 `recorded_sha256`，保留之前记录的摘要。核对由调用触发，来源不可用、未确认或身份不符时不读取引用文件。

核对结束前会再比对已观察路径的文件状态，无需重复读取文件内容。之后发生的修改会在下一次核对时反映。

修复缺失路径时，研究者在同一来源选择一个尚未登记的文件。核对确认候选文件的摘要与原版本相同，并确认旧路径仍缺失。修复保留引用 ID 和摘要，只更新引用路径和版本。请求已过期时，应读回当前来源和引用再重试。

### 后台监测来源

原生工作台只监测当前课题已登记的文件引用。打开期间约每秒核对一批，每批最多 16 条。第一次逐批比对当前摘要与保存的版本。后续只在文件元数据变化时重算摘要，读到不稳定状态时重试。重开会补查关闭期间仍然存在的修改。关闭工作台会结束监测。

通过本机会话认证后，工作台可以从 `GET /api/source-observations` 读取当前快照。未启用或正在核对的来源没有文件观察结果。完成核对后返回来源绑定版本、登记的引用 ID，以及已保存的摘要和可取得的当前摘要。会话快照变化时更新其版本号。返回中没有文件位置或内容。监测保留原目录和已确认的摘要。

## 核验签名构建

在软件目录和 App 之外新建虚拟环境，运行[已安装 wheel 的兼容回归](../tests/compat_validation/README.md)。安装与 `tests/compat_validation/PACKAGE_VERSION` 一致的 wheel，课题、数据库和日志都使用临时位置。若 Python 或软件包来自 macOS App 内部，回归入口会在启动测试前拒绝执行。

用签名 App 和独立的应用配置，从 Launchpad 在[本机 Lean 和 PostgreSQL](research-foundation.md)上验收。确认首次打开自动建库，重开后恢复到同一课题。用一个库内公开课题和另一个外置公开课题核对两条独立数据库绑定及核验记录。在存储设置预览并迁移到未占用的位置，再打开两个课题，比对 ID、证据和文件。确认目标不可用时原库仍能打开。

退出后，对同一个 App 重新检查签名。

```sh
codesign --verify --deep --strict /absolute/path/to/local-review/Trellin.app
```
