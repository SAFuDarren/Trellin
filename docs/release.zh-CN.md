# 发布准备

[English](release.md) · 简体中文

发布物包括 Python 包、通用 Lean 验证器和 Mathlib 配置、迁移文件及模式契约。案例材料和评测数据保存在独立目录中。研究输入、运行记录、凭据和数据库快照属于各项目工作区。

## 核对发布物

在独立的工作区构建 wheel 和源码包。在干净的环境中安装 wheel 的 PostgreSQL 附加依赖，用一次性数据库和固定的 Lean 环境跑[仓库回归与兼容回归](../CONTRIBUTING.md#run-the-compatibility-regressions)。在源码目录外确认已安装命令可以准备通用 Lean 环境。从上一受支持的数据库修订号检查升级，并重放一条已保存的完整运行记录。候选包应通过 PostgreSQL 套件和必跑的 `release-lean` 用例。更广的 `lean` 套件及其可选输入单独记录。

## 核对首次使用

使用配套的外部 `first-proof` 案例。从干净虚拟环境、空数据库和独立项目目录开始，按其 README 核对准确命题与前提、核验并采纳证明、在另一项主张的已审定基础上复用证明，再确认撤回前提会使依赖证据失效。这个流程无需模型服务。案例输入和运行记录放在软件发布物之外。

把配套的 wheel、源码包、`research_multiplier-<version>-first-proof.tar.gz` 和 `SHA256SUMS` 放到同一发布标签。入门案例包以 `first-proof/README.md` 为入口。CI 使用仓库中对应版本的兼容性测试源码，历史候选构建可使用单独核验过的验证包。发布前按快速入门核对文件名和 SHA-256。

确认 wheel 和源码包包含项目 [Apache License 2.0](../LICENSE) 和 [NOTICE](../NOTICE)，包元数据声明 `Apache-2.0`。生成 `SHA256SUMS` 前，把许可证和声明放入入门案例包。打包原样保留的兼容测试源码时，保留测试套件原有的 MIT 许可证。

## 演练版本恢复

首次公开分发前，以及执行不兼容升级前，在一次性课题上演练。原项目和恢复目标各用一个 PostgreSQL 数据库。将上一个版本和候选版本的 wheel 连同 PostgreSQL 附加依赖安装到独立虚拟环境，记录每份 wheel 的版本、源码提交和已核验的 SHA-256。首次公开发布之前，可以使用已核验摘要的内部构建作为上一个版本。用对应环境的 `research-multiplier` 执行下列子命令，需要工作区的命令应指向选定的课题目录。

1. 用上一个版本核验并采纳公开入门案例中的证明，保存一条离线运行记录。记录数据库修订号、冻结命题、核验收据及运行记录路径。用获授权的源数据库 URL 执行 `research backup-project --out ARCHIVE`，再执行 `research verify-project-backup ARCHIVE`。
2. 在候选版本环境中，对同一个一次性数据库执行[迁移命令](research-foundation.md#set-up-the-workspace)。记录迁移后的修订号，确认候选版本能读取冻结命题和原核验收据、重放旧记录并保存一条新记录。
3. 切回上一个版本的环境。把 `RM_MIGRATION_DSN` 指向新建的空数据库，执行 `research restore-project ARCHIVE RESTORED_DIRECTORY` 并配置这个数据库的登录信息。核对新工作区与数据库的绑定，比较恢复后的冻结命题及核验收据，再用上一个版本重放归档记录。根据清单核验摘要、比对文件，工作区和数据库标识应更新。备份后新增的工作应留在升级后的原工作区。
4. 每次发布审阅都附上最近一次适用的演练结果，存放在源码目录之外。记录构建摘要、源码提交、数据库修订号、比对结果和恢复命令。备份与恢复选项见[存档操作指南](research-foundation.md#recover-and-monitor)。

### Issue #17 的内部演练

已归档的 1.0.1 wheel 构建自 `2daacac`，其源码树与 `893582e` 一致，本次也从 `cb9a3cd` 构建了 1.0.3 wheel。两份构建分别在独立环境中运行，使用本机 PostgreSQL 和 Lean 4.19.0。候选版读取了原冻结命题和证明收据，重放旧记录并保存新记录。上一个版本把升级前的存档恢复到新库，核验了摘要，读取同一命题及收据，并重放了归档记录。16 份归档项目文件逐字节一致，工作区与数据库标识按预期更新。候选版新增的运行记录没有进入恢复后的工作区。两份 wheel 的数据库修订号均为 `0071`，本次覆盖同一数据库修订号下的软件版本回退。

## 记录发布结果

记录发布版本、支持的 Python 与 Lean 版本、前后数据库修订号以及发布物的摘要。将版本对应的回归存档和 SHA-256 随审阅记录保存，并保留已执行测试线的外部日志，包括跳过的可选输入。发布前确认仓库归属、可见性和项目许可证。部署凭据留在运行配置中。

从 [pyproject.toml](../pyproject.toml) 查看源码版本，从包内 Alembic 迁移文件确定数据库修订号。升级正在使用的项目之前，先阅读[工作区备份与迁移指南](research-foundation.md#set-up-the-workspace)。支持的功能见[研究工作流](README.md#research-workflows)。
