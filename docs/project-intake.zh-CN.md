# 课题开始与定理录入

打开绑定本机 PostgreSQL 的工作台。两个入口都可以在课题还没有命题时使用。

## 与 AI 梳理

点「和 AI 梳理资料」，填写标题、方向和想弄清的问题，粘贴需要整理的文字，或选择支持的文本文件。私有材料可选本机 Ollama 模型生成草稿。公开摘录可选择已在「设置 → 模型连接」添加的模型。先核对预览里的摘录、研究目标和服务商，然后点「发送这段公开摘录」。

候选项会引用对应的原文。逐条查看提出的定义、假设和定理及其形式化，决定哪些可以进入起始依据，并填写本人的审查信息。形式化尚有歧义的条目可以补清楚后再采纳，也可以先排除。草稿可以重新打开。AI 提取的结果需要你亲自确认，之后的证明推进仍绑定你确认的命题和授权。

### 连接模型

点「设置 → 模型连接 → 添加连接」。Codex 或 Claude Code 使用已安装的命令，并通过服务商原生流程登录。Trellin 找不到命令时可指定绝对路径。直连 OpenAI 或 Anthropic API 时填写模型标识和自己的 API 密钥。新增的 API 密钥保存在 macOS 钥匙串。连接列表只显示你添加的模型。

「测试连接」发送一条固定请求，内容与课题无关。「移除连接」后，该连接不会再接收新请求，已有模型结果和核验记录留在项目中。使用本机模型时先启动 Ollama，并确保已下载支持文本的模型。

## 添加定理

点「手动添加定理」，填写自然语言陈述和精确的 Lean 命题，再选择它的用途。

- **已有定理**保存为库草稿。可填写来源，之后查看保存的原文和 Lean 陈述并确认该版本。确认形式化记录你对陈述含义的判断，已核验的证明另有证据记录。
- **待证明命题**保存你确认的研究目标。直接录入自包含的 Lean 命题时，请把明示的前提写入命题的绑定变量并确认。确认后的目标出现在命题列表。Lean 核验以及额外项目依据的确认沿用现有流程。

本地模型不可用时，仍可添加和审查定理。
